## Test 3｜IMU / PCA / DRV2605L

状态：PARTIAL PASS / HAPTIC INTERMITTENT

已完成：

1. PCA9540B：0x70 稳定通信。
2. 当前上游 0x68 器件稳定 CHIP_ID=0x27，可按 BMI260 配置完成初始化并输出 Accel/Gyro 六轴数据。
3. INT1 Data Ready：PASS / STRONG。INT1_IO_CTRL=0x0A、INT_LATCH=0x00、INT_MAP_DATA=0x04；启动前约 3 秒存在正常过渡，之后 IRQ 计数稳定约 93~101 次/秒，total 持续增长；INT_STATUS_1 在有效时读到 0xC0。
4. 两颗 DRV2605L 已重新焊接；PCA CH0 时存在 `0x5A`，PCA CH1 时也存在 `0x5A`，因此两颗器件的 I2C 控制链路均可通信。

Haptic 故障与恢复记录：

1. CH0 ROM effect 15 曾正常结束。
2. CH1 ROM effect 15 曾出现 `GO timeout` / PLAY FAIL。
3. 强 RTP 测试曾出现 CH0 STATUS=`0xE5`、CH1 STATUS=`0xE1`；两者 bit0 均为 1，即 `OC_DETECT=1`。
4. 后续没有重新烧录程序、没有更改固件，但振动又恢复正常。
5. DRV2605L 的 OC_DETECT 为锁存过流标志；器件在负载阻抗恢复到阈值以上时会周期性尝试重启，因此“突然又能工作”与保护自动恢复相容，也与间歇性短路/接触问题相容。
6. 因此当前不能把问题关闭，也不能单凭恢复现象判断一定是软件、一定是芯片损坏或一定是焊接问题。

当前诊断优先级：

1. **间歇性 OUT+/OUT− 低阻或焊接/接触问题**：优先级高。
2. **LRA / 连接点瞬态低阻或机械接触变化**：优先级高。
3. **DRV2605L 过流保护触发后自动恢复**：与现象直接相符。
4. **固定的软件逻辑错误**：概率下降，因为没有重新烧录却恢复。
5. **LRA 参数未完成 Auto Calibration / Rated Voltage / OD Clamp 优化**：仍需后续处理，但不能解释所有 OC 现象。

下一步不是继续加大振动，而是做重复性验证：

- 固定只测一个通道，优先 CH1 / LRA B。
- 使用低/中幅度短脉冲，不再使用长时间 `0x7F` RTP。
- 连续 20~50 轮上电/振动，逐轮记录 STATUS，确认是否再次出现 GO timeout / OC_DETECT。
- 测试期间轻微触碰/轻压 DRV、LRA 焊点、板边，观察故障是否随机械扰动复现；若明显相关，优先重焊/检查焊盘。
- 故障复现时立即断电测 OUT+↔OUT-、OUT±↔GND、OUT±↔VDD，并和另一通道对比。
- 必要时抬起 LRA 一端，将“执行器/连线”和“PCB/DRV”隔离判断。

正式 BMI270 仍需 CHIP_ID=0x24 的真实器件重新验证，并在正式器件上复测六轴与 INT1。
