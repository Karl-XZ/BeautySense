## Test 4｜Camera / MIC / Audio

状态：CAMERA VIDEO PASS / MIC NEXT

Camera 已完成：

1. XCLK：GPIO15，Camera 初始化及视频工作正常。
2. SCCB：GPIO1 SDA / GPIO2 SCL。
3. Camera SCCB 扫描：仅发现 0x3C。
4. OV5640 SCCB ACK：PASS。
5. 读取 0x300A = 0x56。
6. 读取 0x300B = 0x40。
7. 合并 CHIP_ID = 0x5640：PASS。
8. 连续重复读取 CHIP_ID 均为 0x5640，基础控制链路稳定。
9. DVP 数据链路：D0~D7、PCLK、HREF、VSYNC 已通过实际抓帧与连续视频工作得到功能性验证。
10. ESP32-S3 `esp_camera` 初始化成功，PSRAM framebuffer 正常使用。
11. OV5640 JPEG → ESP32-S3 → PSRAM → Wi-Fi → 浏览器 MJPEG 实时视频：PASS。
12. 浏览器已实际看到连续实时画面；因此 Camera 整体功能链路判定 PASS。

说明：当前结论是功能链路 PASS，不等于已对每一根 DVP 信号做示波器级独立电气质量认证。

下一步：

1. MIC 时钟 / PCM 数据。
2. MAX98357A I²S / SD/EN / BTL 差分输出。
3. 两只 8Ω 骨传导并联，从低音量开始验证声音、失真、温升、电流。
4. ZTS6672 仅作为候选验证，不自动替代 ICS-43434 基线。

## Test 5｜整机稳定性 / 结构基准

1. 同时运行 Wi-Fi + IMU + Camera + MIC/Audio + Haptic。
2. 电池和5V供电分别测试。
3. 连续运行 30–60 min，记录掉线、I2C错误、掉帧、音频异常、重启。
4. 冷启动至少 20 次。
5. FPC轻微弯折、板边轻压下观察间歇故障。
6. 检查器件高度、接口可达性、天线净空、结构干涉、真实尺寸。
7. 最终按 PCB / BOM / Firmware / Structure 输出 V2 修改项。
